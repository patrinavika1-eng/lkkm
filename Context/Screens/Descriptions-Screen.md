## Screen-001 — Задачник
- Скриншоты: `Screen_1.webp` – `Screen_13.webp`
- Исходное имя/ссылка: `images/2.webp`–`14.webp` (вложения пользователя); текстовое описание совпадает с публичной документацией `instructions.x5.ru` (см. `Context/Materials/Zadachnik-Instructions.md`, `Zadachnik-Dashboard-Instructions.md`)
- Платформа: Веб
- Раздел/маршрут: Задачник (см. Information-Architecture.md)
- Источник: S-004 (текст документации), S-005 (скриншоты, 1-я партия), S-006 (скриншоты и пояснение пользователя, 2-я партия — автоповтор по неделям/месяцам, загрузка из файла), S-007 (скриншоты + текст, 3-я партия — вкладка «Дашборд»)

### Назначение
Раздел для контроля рабочих задач КМ: просмотр и изменение статуса задач, создание задач для себя или других сотрудников, настройка автоматизации регулярных задач (автоповтор), просмотр аналитики по задачам (вкладка «Дашборд»). Источник: S-004.

### Пользователи и права
Наблюдаемое: переназначить задачу на другого сотрудника может текущий исполнитель задачи; изменять задачу (редактировать) может только её создатель, и только пока задача в статусе «Открыта» или «В работе». Общая ролевая принадлежность раздела (КМ, руководители) — см. Users.md, Information-Architecture.md. Источник: S-004.

### Ограничения
- До 50 исполнителей на одну задачу. Источник: S-004.
- Вложения: не более 10 файлов, до 60 МБ каждый, форматы jpg/png/pdf/doc/xls/csv/msg/zip. Источник: S-004, S-005.
- Редактировать задачу может только её создатель, и только в статусе «Открыта» или «В работе». Источник: S-004.
- Переназначить задачу может только текущий исполнитель. Источник: S-004.
- Загрузка задач из файла: не более 1 файла, до 10 МБ, формат Excel. Источник: S-006.

### Неопределённости
- Вкладка «История» карточки задачи не показана на скриншотах — содержимое не подтверждено (см. Discovery.md H-003).
- Вкладка «Автоматизация» (список правил автоповтора) описана текстом, но не проиллюстрирована скриншотами.
- Шаг «накликивания» сотрудников для предзаполнения Excel-шаблона (упомянут пользователем) не проиллюстрирован отдельным скриншотом — не подтверждено, где и как именно выбираются сотрудники до скачивания шаблона (см. Discovery.md H-004).
- Точный состав «Доп. фильтров» на вкладке «Дашборд» → «Все задачи» (должность, финкод/дирекция, геозона) не проиллюстрирован раскрытым видом — известен только из текста.

- Платформа: Веб
- Раздел/маршрут: в интервью (Information-Architecture.md) этот раздел назывался «Матрица доступов»; фактическое название в интерфейсе — «Матрица ответственных» (подтверждено скриншотом breadcrumb). Считаю это одним разделом под двумя названиями — см. Discovery.md Q-005.
- Источник: S-008 (скриншоты + подробная текстовая спецификация)

### Назначение
Раздел для управления зонами ответственности сотрудников: привязка к геозонам, финкодам/дирекциям, функциям, категориям, ценовым сегментам, поставщикам; роль «капитан» по региону/ФК/поставщику; управление доступом (роли Обычный сотрудник/Администратор/Руководитель/Суперпользователь) и журналирование изменений («История действий»). Источник: S-008.

### Пользователи и права
Наблюдаемое — формальная ролевая модель раздела (дополняет Users.md):

| Роль | Права в разделе | Индикатор |
|---|---|---|
| Обычный сотрудник | Не видит карандаши редактирования; редактирование недоступно; видит баннер «Чтобы изменить информацию о себе, напишите своему руководителю [email]»; может запросить роль суперпользователя | — |
| Администратор (не руководитель) | Редактирует данные сотрудников своей группы (активные карандаши); для недоступных сотрудников — неактивная иконка-замок с тултипом; может запросить роль суперпользователя | Бронзовая звезда |
| Руководитель | Как администратор + может назначать/снимать администраторов своей группы через отдельный флоу; может запросить роль суперпользователя | Серебряная звезда |
| Суперпользователь | Подразумевается полный доступ к редактированию всех сотрудников сети (роль выдаётся по запросу, сам процесс одобрения не показан) | Золотая звезда |

Источник: S-008.

### Ограничения
- Карандаш редактирования активен только у администратора/руководителя/суперпользователя и только для сотрудников в зоне его ответственности. Источник: S-008.
- Капитан ФК нельзя назначить без предварительного выбора капитана региона/ФК-ЦО; капитан поставщика — без капитана ФК; УИ-3 — без постоянного ФК; УИ-4 — без УИ-3 (жёсткая последовательность выбора). Источник: S-008.
- Временный ФК обязательно сопровождается периодом действия. Источник: S-008.
- Список торговых сетей для запроса доступа ограничен тремя вариантами: Чижик, Пятёрочка, Перекрёсток. Источник: S-008.
- Доступные колонки таблицы ограничены 11 (фиксированный набор, можно скрывать/показывать и переставлять, но не добавлять новые). Источник: S-008.

### Неопределённости
- Соотношение названий «Матрица доступов» (из интервью) и «Матрица ответственных» (фактическое название в интерфейсе) не подтверждено пользователем явно — см. Discovery.md Q-005.
- Сам процесс одобрения запроса на роль суперпользователя (кто и как его обрабатывает) не описан и не показан.
- Поведение сайдбара редактирования при серверной ошибке (остаётся ли открытым) помечено как гипотеза H-006 — в тексте явно сказано только «добавляется обработка ошибки с бека», без деталей UI.
- Точное поведение кнопки «Скачать Excel» (что именно выгружается — все строки/с учётом фильтров) не детализировано.
- Связь между УИ-3/УИ-4 здесь и ранее упомянутым «УИ4» в контексте приборной панели (H-001) не подтверждена — возможно, это один и тот же уровень иерархии, используемый в разных местах интерфейса.
